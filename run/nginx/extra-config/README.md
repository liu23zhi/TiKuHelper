# 可选 Nginx 扩展

宿主机目录是 `run/nginx/extra-config/`，Compose 将它只读映射到容器 `/app/nginx-extra`。不要再创建或使用旧路径 `run/nginx-extra/`。本目录可以只保留本 README；只有 `.conf` 和 `.inc` 文件会被网关读取。

## 当前工作方式

- 网关始终以镜像内置模板为基础，不直接把本目录当成完整的 `nginx.conf`。
- 网关递归读取本目录中的普通文件，将文件复制到运行时私有 generation，再合并到生成配置中。
- 扩展内容是在生成的 `http { ... }` 上下文中加载的：完整 `server { ... }` 配置适合放在 `.conf`；`add_header`、`map` 等适合 HTTP 上下文的片段可放在 `.inc`。
- `user`、`worker_processes`、`events { ... }`、`http { ... }`、`stream { ... }` 等顶层配置不能放在这里；单独的 `location { ... }`、`proxy_pass ...` 等缺少上层上下文的片段也不能直接使用。
- 文件变更由网关周期检查，生成候选后执行 `nginx -t`，确认 reload 成功才替换活动配置。通常不需要重启容器。

## 明确禁止的内容

以下内容由服务端生成或属于安全边界，放入扩展文件会被跳过：

- `upstream tiku_adapter`
- `log_format tiku_safe`
- `map $http_upgrade`
- `/api/Wechat_qc_code` 路由
- `8060`、`8680`、`9043` 监听
- `default_server` 或 `server_name _`
- 重新 include `/etc/nginx/conf.d/` 生成配置

扩展配置不能覆盖普通站、脚本站、二维码路由、TLS 证书选择或现有鉴权规则。需要新增站点时只能使用未占用的监听地址/端口和明确的 `server_name`，并确保请求不会绕过应用的 Host 校验。

## 已知问题和失败行为

1. 单个文件的语法错误、保留指令或与已接受扩展冲突时，网关会在日志中记录原因并跳过该文件；其它已经通过校验的文件继续保留。
2. 文件是按扫描顺序逐个加入候选配置的，因此两个文件之间的冲突可能导致后加入的文件被跳过。不要依赖文件名顺序覆盖前一个配置。
3. 这些跳过信息只写入容器日志，不会在 WebUI 中显示。排查时查看 `docker logs tikuhelper`，并确认最终生成配置是否生效。
4. 如果镜像内置模板、证书快照或所有扩展合并后的最终配置整体校验失败，网关会保留旧活动配置；首次启动且没有可用旧快照时，容器可能无法正常启动。扩展文件“通常单独跳过”不等于任何配置错误都能保证首次启动成功。
5. 删除或修改扩展文件后，网关会重新生成候选配置；reload 失败时保留旧配置，不会自动把错误文件写入活动配置。

新增配置前请先在隔离环境用 `nginx -t` 验证，并只提交最小的 `.conf` / `.inc` 文件。不要把完整 Nginx 主配置、备份包、日志或证书放入本目录。
